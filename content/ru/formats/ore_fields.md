# Рудные поля

Данные о руде разделены на два уровня: **на уровне типа** (`minerals` — что представляет собой материал и сколько даёт одна добыча) и **на уровне зоны и типа** (`mineralconfigs` — сколько узлов, какого они размера и насколько заполнены). Состояние узлов во время работы сервера хранится в таблице `mineralnodes`.

## Таблица `minerals`

| Колонка | Тип | Используется в | Назначение |
|---|---|---|---|
| `idx` | int | `(MaterialType) idx` | Порядковый номер перечисления `MaterialType` (1=Titan … 19=DHDT, 0=Undefined). Все объединения используют `mineralconfigs.materialtype = minerals.idx`. |
| `name` | varchar | `ToMaterialType()` | Название типа ("titan", "crude", …). |
| `definition` | int | `MaterialHelper` → item | Определение предмета, получаемого при добыче (например, titan → def 168). |
| `amount` | int | `DrillerModule` | **Базовое количество за цикл бурения** (titan 1500, crude 1500, stermonit 975, liquizit 450, epriton 450, …). |
| `extractionType` | int | `TerrainsModule` | 0 = Твёрдое вещество (`OreLayer`), 1 = Жидкость (`LiquidLayer`). |
| `enablereffectrequired` | bit | ограничение модулей | Требуется ли эффект-активатор для добычи. |
| `geoscandocument` | int | предметы сканирования | Предмет геосканирования для данного материала. |

## Таблица `mineralconfigs`

Одна запись на пару (зона, материал). Обрабатывается классом `MineralConfigurationReader` → один `MineralLayer` на строку:

| Колонка | Тип | Используется в | Назначение |
|---|---|---|---|
| `zoneId` | int | построение слоя | ID зоны-владельца. |
| `materialtype` | int | → `minerals.idx` | Тип материала. |
| `maxnodes` | int | `MineralLayer.LoadMineralNodes` | Количество узлов данного типа, поддерживаемое зоной. |
| `maxtilespernode` | int | генератор | Максимальное количество тайлов на пятно узла; также определяет радиус расстановки (см. ниже). |
| `totalamountpernode` | int | генератор | Общее количество материала в новой жиле, распределённое по тайлам пятна. |
| `minthreshold` | double | генератор | Минимальное нормализованное заполнение тайла (0–1); тайлы ниже порога отбрасываются. |

### Формулы генерации узлов (`MineralNodeGeneratorBase.cs`)

Для нового узла типа с конфигурацией выше:

```
radius  = floor( sqrt(maxtilespernode / π) ) × 2
spacing = начальная позиция должна быть ≥ 2 × radius от ближайшего существующего узла
blob    = случайное блуждание (flood fill кистью 4 тайла) до maxtilespernode допустимых тайлов
tile[i] = ( noise[i] / max(noise) ), нормализованный в диапазон [minthreshold, 1]
         × (tile[i] / Σtile) × totalamountpernode
         × uniform(0.9, 1.1)          // случайное отклонение, затем округление до uint
```

Зоны отчуждения вокруг док-баз и телепортов (`KeepOutDist`): epriton = 100 тайлов (`MINERAL_DISTANCE_FROM_BASE_MIN`), flux ore = 200; все остальные типы = 0.

### Пример расчета — Daoden (zone_ASI), нефть crude (id 2)

`maxnodes=8, maxtilespernode=1257, totalamountpernode=125,000,000, minthreshold=0.5`:

```
radius  = floor(√(1257/π)) × 2 = floor(20.0) × 2 = 40   → расстояние между узлами ≥ 80 тайлов
blob    = до 1257 тайлов
tile    = доля ∈ [0.5, 1.0] × (125,000,000 / Σnormalized) × случайное отклонение
```

Полный узел нефти (crude) содержит 125 млн единиц; при базовой добыче 1500 единиц за цикл бурения это составляет ~83 000 циклов добычи на узел и ~666 000 суммарно на 8 узлов зоны.

## Состояние узлов — `mineralnodes`

| Колонка | Назначение |
|---|---|
| `zoneid`, `materialtype` | Зона-владелец + тип материала |
| `x, y, width, height` | Ограничивающий прямоугольник узла (область пятна) |
| `data` | Сжатый массив `uint` для каждого тайла (построчно внутри прямоугольника) |

Жизненный цикл (`MineralNode.cs`, `MineralLayer.cs`):

- **Загрузка (Load)**: при старте зоны загружаются все сохраненные узлы; узел, остаток которого составляет ≤ **1%** от `totalamountpernode`, удаляется.
- **Пополнение (Top-up)**: если уцелело меньше `maxnodes`, генерируются новые узлы (по формуле выше).
- **Истечение срока (Expiry)**: **нетронутый** узел исчезает через **7 дней** (`TimeTracker`); добыча сбрасывает таймер. Узел, максимальное значение тайла которого падает до 0, также исчезает.
- **Сохранение (Persistence)**: измененные узлы сбрасываются в БД по таймеру каждые **30 минут**.
- **Связь с потоковой рудой (Flux ore coupling)**: истощение или удаление узла `FluxOre` публикует сообщение `OreNpcSpawnMessage` → спавнер NPC обрабатывает его (`OreNPCSpawner`).

## Механика добычи (`MineralExtractor.cs`, `DrillerModule.cs`)

Объем добычи равен `minerals.amount`, умноженному на свойство робота `mining_amount_modifier` (агрегируется из `mining_amount_modifier`, `effect_mining_amount_modifier`, `drone_amplification_mining_amount_modifier`, `effect_excavator_mining_amount_modifier`).

- **Твёрдая руда** (`OreLayer`): берет `min(tile value, amount)` с **одного тайла**, на котором стоит робот.
- **Жидкая руда** (`LiquidLayer`): откачивает ресурс со **всего узла**, начиная с ближайших тайлов (очередь с приоритетом по квадрату расстояния), пока не наберется нужный объем.
- **Гравий** (только в обучающих зонах, `GravelLayer`): считывает значение тайла, но не уменьшает его — узлы гравия неисчерпаемы.

Выход продукции при переработке руд приведён в разделе [Руды](/content/ores/); количество жил по зонам указано в [Индексе зон](/zones/zone-index/).
