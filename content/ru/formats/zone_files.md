# Файлы зон

Террейн зоны хранится в виде набора **бинарных файлов слоев** (по одному файлу на слой), расположенных рядом с данными зоны. Формат имени: `{layer}.{zoneid:0000}.bin` (`Zone.CreateTerrainDataFilename`) — например, `plants.0042.bin` для зоны 42. Слои представляют собой плоские массивы структур фиксированного размера с построчным порядком хранения (**row-major, ширина × высота**; по умолчанию 2048×2048 = 4 194 304 тайла).

## Слои

| Файл | Структура | Байт/тайл | Содержимое |
|---|---|---|---|
| `blocks.NNNN.bin` | `BlockingInfo` | 2 | `flags` (байт) + `height` (байт) — препятствия, растения, декор, острова |
| `control.NNNN.bin` | `TerrainControlFlags` | 2 (или 1) | биты управления для каждого тайла (см. особенность ниже) |
| `plants.NNNN.bin` | `PlantInfo` | 7 | состояние растений для каждого тайла (см. ниже) |
| `altitude.NNNN.bin` | `ushort` | 2 | высота; при проверках растений сравнивается как `value / 4` (масштабирование под клиентские координаты) |
| `altitude_blend.NNNN.bin` | `ushort` | 2 | только для терраформируемых зон: маска смешивания (blend mask) для каждого тайла (см. ниже) |
| `altitude_original.NNNN.bin` | `ushort` | 2 | только для терраформируемых зон: исходная высота до терраформирования на диске — **сервером не читается** (см. ниже) |

Производные слои (вычисляются при загрузке, **не** являются файлами): `SlopeLayer` (из altitude) и `Passable` (из blocks + slope + проходимые позиции из БД, только для нетерраформируемых зон). В терраформируемых зонах слой высоты оборачивается в `TerraformableAltitude`, который при загрузке рассчитывает диапазон **барьера (barrier)** для каждого тайла: значение `blend/65535` интерполирует константы 1850 → исходная высота (min) и 30000 → исходная высота (max), после чего диапазон ограничивается так, чтобы он всегда включал текущее значение. Обновления терраформированной высоты зажимаются (clamp) в пределах этого барьера: таким образом, `blend = 0` оставляет тайл свободно терраформируемым в диапазоне от 1850 до 30000, а `blend = 65535` жестко фиксирует его на исходной высоте. (Файлы `altitude_original.NNNN.bin` на диске содержат исходную высоту до терраформирования для внешних инструментов; сервер делает снимок исходной высоты в памяти из загруженного `altitude.NNNN.bin` и никогда не читает файл с этим именем.)

### `BlockingInfo` (2 байта)

Поле `flags` имеет тип `BlockingFlags` (байт):

| Бит | Название |
|---|---|
| 1 | Obstacle |
| 2 | Plant |
| 4 | Decor |
| 8 | Island |

`NonNaturally` = Decor \| Island \| Obstacle. `height` — высота блокировки перемещения по тайлу (высота блокировки растениями записывается сюда кодом роста растений).

### `TerrainControlFlags` (слой управления)

Набор флагов типа `ushort`:

| Бит | Название |
|---|---|
| 1 | AntiPlant |
| 2 | TerraformProtected |
| 4 | SyndicateArea |
| 8 | ConcreteA |
| 16 | ConcreteB |
| 64 | Roaming |
| 128 | Highway |
| 256 | PBSHighway |
| 512 | PBSTerraformProtected |
| 1024 | NpcRestricted |

(Нумерация 512/1024 соответствует `1 << n`; бит 32 не используется.) Размещение растений на тайле разрешено, если `!(AntiPlant || Roaming || Highway || PBSHighway || ConcreteA || ConcreteB)`.

**Особенность хранения**: загрузчик поддерживает файлы управления как с **1 байтом/тайл**, так и с **2 байтами/тайл** — если размер файла равен количеству тайлов, каждый байт расширяется до `TerrainControlFlags`; в противном случае считывается сырой массив `ushort` (`LayerFileIO.LoadLayerData`). Все действующие зоны используют **2-байтовый формат** (`control.0000.bin` = 8 388 608 Б = 4 194 304 × 2); 1-байтовый формат (4 МБ) является устаревшим резервным вариантом, который загрузчик все еще поддерживает.

### `PlantInfo` (7 байт) — состояние тайла растения

| Байт | Поле | Значение |
|---|---|---|
| 0 | `type` | `PlantType` (0 = пусто; 1..19 согласно [Plant fields](/ru/formats/plant-fields/)) |
| 1 | `state` | Индекс стадии роста (в таблице `state_N` соответствующего правила) |
| 2 | `time` | Аккумулятор тиков роста (сравнивается с `growRate` из правила) |
| 3 | `spawn` | **Вероятность спавна на тайле, запеченная в файл зоны; сервер никогда ее не перезаписывает** (в коде нет ни одного присваивания — `PlantInfo.Clear()` намеренно сохраняет это значение). 0 = бесплодный тайл: любое растение на нем немедленно удаляется во время валидации, и новые растения никогда не прорастают. В остальных случаях это фильтр вероятности попытки: во время фазы регенерации растений случайный пустой тайл принимается только в том случае, если `FastRandom.NextByte() < spawn`, т. е. шанс прохождения для тайла составляет ≈ `spawn/256`. |
| 4 | `health` | Текущее HP (доля от здоровья стадии из правила) |
| 5 | `material` | Текущее количество плодов (0–255) |
| 6 | `groundType` | Байт `GroundType` (0=Darkrocks … 17=Sand-ish, 20=undefined) — класс террейна, с которым сверяется `allowedTerrainTypes` из правила растения |

### Практический пример — размеры файлов для зоны 2048×2048 (проверено на реальных файлах)

```
blocks    4,194,304 tiles × 2 B = 8,388,608 B (8 MB)
plants    4,194,304 tiles × 7 B = 29,360,128 B (28 MB)
altitude  4,194,304 tiles × 2 B = 8,388,608 B (8 MB)
control   4,194,304 tiles × 2 B = 8,388,608 B (8 MB, 2-byte form; a 1-byte legacy file would be 4 MB)
```

**Проверка на реальных данных** (`plants.0106.bin`, терраформируемая гамма-зона): все 4 194 304 тайла содержат `spawn = 0x83` (шанс 131/256 ≈ 51% на попытку) и `type = 0`, за исключением 10 тайлов с живыми растениями — карта спавна представляет собой запеченное поле вероятностей для всей зоны, не зависящее от текущего расположения растений.

Не во всех зонах присутствуют все файлы: 66 из 84 зон поставляются с `plants.NNNN.bin`. 18 зон без этого файла — устаревшие варианты гамма-зон (`zone_tm_g_*`, `zone_ics_g_*`, `zone_asi_g_*`, идентификаторы 20–43), которые не загружаются. Каталог слоев: `$GameRoot/layers/`.

## Цикл сохранения (`IntervalLayerSaver.cs`)

- За каждым изменяемым слоем (blocks, control, plants, altitude) следит `IntervalLayerSaver<T>`; любая запись в тайл или область устанавливает флаг изменения (dirty flag).
- Процесс сохранения регистрируется с таймером на **2 часа** (`TerrainsModule`); измененный слой записывается при срабатывании тика.
- Запись производится в файл `.tmp<ticks>.bin`, проходит **проверку MD5** путем повторного чтения, и только после этого файл заменяет собой исходный.
- При остановке сервера измененные слои сохраняются еще раз.
- Минеральные жилы **не** содержатся в этих файлах — они сохраняются в таблицу БД `mineralnodes` (сброс каждые 30 минут, см. [Ore fields](/ru/formats/ore-fields/)).

## Что хранится в файлах, а что нет

| Данные | Где хранятся |
|---|---|
| Слои террейна (blocks/control/plants/altitude) | Файлы `.bin` |
| Состояние рудных жил | БД `mineralnodes` |
| Виды растений для зоны | БД `plantrules` + **файлы** правил (`$GameRoot/plantrules/*.txt`) |
| Конфигурация зоны (плодородие, размер, тип, набор правил) | БД `zones` |
| Конфигурация руды | БД `mineralconfigs` |
