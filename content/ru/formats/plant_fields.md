# Поля растений

Поведение растений определяется для каждого вида **файлом правил** (обычный текст) в каталоге `$GameRoot/plantrules/`. Привязка файлов к зоне задается таблицей БД `plantrules(idx, plantrule, rulesetid)` → `zones.plantruleset`; загрузка и объединение выполняются в `PlantRuleLoader.cs`, а сопоставление полей с объектом — в `PlantRule.cs`.

## Формат файла

Одна пара `ключ=значение` на строку; комментарии вида `//` отбрасываются. Значения используют **символы токенов GenXY** (`GenxyReader.cs` — первый символ определяет тип и систему счисления):

| Токен | Тип при разборе | Пример |
|---|---|---|
| `n` | int, десятичное | `n125`, `n-1` |
| `N` | int[], десятичный массив через запятую | `N5,5,5,5` |
| `f` | double, десятичное | `f0.1` |
| `$` | string | `$prismocitae` |
| `i` | int, **шестнадцатеричное** | `iFF` |
| `L` | long, **шестнадцатеричное** | `L100` |
| `4` | int[], **шестнадцатеричный массив** | `41,2,3` → [1, 2, 3] |

### ⚠ Ловушка «массива без префикса»

В файлах также встречаются значения вроде `blockingHeight=40,3,3,4` **без явного префикса токена**. Парсер не делает для них исключений: начальная цифра `4` воспринимается как токен `IntegerArray` (шестнадцатеричный массив), а остальная часть парсится как hex. Таким образом:

```
blockingHeight=40,3,3,4   →  токен '4' + hex-массив "0,3,3,4"  →  [0, 3, 3, 4]
blockingHeight=N0,8,11,14 →  токен 'N' + десятичный массив      →  [0, 8, 11, 14]
```

Оба варианта превращаются в `int[]`, и начальный `0` — это то, что «поглощает» символ `4`. Поэтому каждый массив без префикса в стандартных файлах игры начинается с `4` — это соглашение гарантирует, что первый элемент сохранит нужное значение. **При создании новых файлов правил явно используйте префикс `N`**; значения ≥ 10 в массиве без явного префикса будут разобраны как шестнадцатеричные и незаметно исказят смысл данных.

### Наследование

Ключ `source=$other_rule.txt` сначала загружает `other_rule.txt`, а затем применяет ключи текущего файла в качестве переопределений (`PlantRuleLoader.LoadRuleByName`). Пример `irontree_t2.txt`:

```
source=$irontree_lo.txt
fruitAmount=n125
```

## Справочник полей правил

Все поля считываются из объединенного словаря настроек (`PlantRule.cs`). Отсутствующие ключи принимают значения по умолчанию, указанные ниже.

| Ключ | Тип / по умолчанию | Используется в | Назначение |
|---|---|---|---|
| `index` | int (0) | `PlantRule.Type` | Значение перечисления `PlantType` для вида (1=GrassA … 19=Devrinol). Также байт `PlantInfo.type`, сохраняемый для каждого тайла. |
| `name` | string | клиентские данные | Отображаемое имя. |
| `fertility` | int (0) | `PlantRuleExtensions.GetWinnerPlantTypeBasedOnFertility` | Вес при взвешенном выборе вида для тайла **без** соседних растений. 0 = никогда не спавнится сам. |
| `spreading` | int (0) | `GetSpreadingBasedWinnerPlantType` | Множитель веса при наличии соседей: вес кандидата = `neighbourCount × spreading`. 0 = никогда не побеждает при распространении. |
| `killDistance` | int (0) | `NatureCube.CheckKillDistance` | Минимальное расстояние до любого существующего растения того же типа; 0/отрицательное = без ограничений. |
| `growRate` | int (0) | `GrowPlantOnTile` | Число тиков куба, которое байт `PlantInfo.time` должен накопить перед шагом машины состояний. Больше = медленнее. |
| `slope` / `minSlope` | int (0) | `ValidateTile` | Допустимый диапазон уклона поверхности. Вне диапазона растение погибает. |
| `allowedAltitudeLow/High` | int (0) | `ValidateTile` | Диапазон высоты относительно `Altitude / 4` (деление на 4 согласуется с координатами клиента). Масштабируется параметром зоны `plantaltitudescale`. |
| `allowedWaterLevelLow/High` | int (0) | `ValidateTile` | Диапазон для `altitude/4 − waterLevel/4` — формирует прибрежную растительность. Также масштабируется по высоте. |
| `allowedTerrainTypes` | int[] (пусто) | `ValidateTile` | Допустимые байты `groundType` (см. [Файлы зон](/ru/formats/zone-files/)). Пусто = нигде не растет. Игнорируется, если включен `allowedOnNonNatural`. |
| `fruitingState` | int (−1) | `GrowPlantOnTile` | Первое состояние, в котором появляются плоды. −1 ⇒ `NotFruiting` (сбор невозможен). |
| `fruitDefinition` | int (−1) | сбор урожая | ID определения предмета плода. |
| `fruitMaterialName` | string | отображение | Название плода (например, `$prismocitae`). |
| `fruitAmount` | byte (0), в пределах 0–255 | `GrowPlantOnTile` | Максимум плодов на растении. При первом входе в состояние плодоношения заполняется 5–15%; каждый следующий тик роста добавляет 15–25% (максимум 100%). |
| `health` | byte[] по состояниям | `GrowPlantOnTile`, бой | Очки прочности (HP) для каждой стадии роста. При переходе в новое состояние текущая **доля** HP сохраняется. |
| `blockingHeight` | int[] по состояниям | `GrowPlantOnTile`, учет спавна | Высота блокировки для каждого состояния; значение `>0` выставляет бит `Plant` в слое блокировки (проходимость=false) и включает растение в целевую плотность зоны. |
| `maxAmount` | int (−1) | `SpawnPlants` | Ограничение на общее число растений данного вида в зоне; −1 = без ограничений. |
| `playerSeeded` | bool (0) | `GetNewPlantRule`, расчет плодородия | Исключается из **всех** естественных спавнов; существует только там, где посажено игроком. |
| `damageScale` | double (1.0) | урон растению | Множитель получаемого урона. |
| `onlyOnUnprotectedZone` | bool (0) | проверка спавна | Растет только в незащищенных зонах. |
| `allowedOnNonNatural` | bool (0) | `ValidateTile` | Пропускает проверки битов управления, типа поверхности и уклона (растет на искусственных тайлах). |
| `placesConcrete` | bool (0) | `GrowPlantOnTile` (смерть) | При гибели снимает биты управления ConcreteA/B под тайлом. |
| `state_N` | int[] | `GetNextState` | Варианты следующего состояния для стадии `N` — каждый элемент выбирается **равновероятно**. |
| `action_N` | int[] | `GetNextState` | Варианты следующего `PlantType` для стадии `N` (равновероятно). Значение `0` (NotDefined) означает **гибель**. |

Согласованность проверяется при загрузке (`CheckConsistency`): `len(health) == len(blockingHeight) == количество состояний`.

## Машина состояний роста

Каждый тик куба 32×32 для каждого тайла с растением (`GrowPlantOnTile`):

1. Если `time < growRate`: `time++`, завершение тика.
2. Иначе: `time = 0`, бросается жребий по `state_N` и `action_N` для текущего состояния:
   - `action == 0` → растение погибает (клиенту отправляется сигнал `type:0, state:1`); если `placesConcrete`, очищается бетон под тайлом.
   - иначе → `type = action`, `state = next`, `health = healthRatio × Health[newState]` (сохраняется процент повреждений).
   - Плоды: если `newState == fruitingState`, `material = fruitAmount × uniform(0.05, 0.15)`; если `newState > fruitingState`, `material += fruitAmount × uniform(0.15, 0.25)` (не выше `fruitAmount`); иначе `material = 0`.
   - Высота блокировки = `blockingHeight[newState]`; бит `Plant` в слое блокировки устанавливается, если `height > 0`.

### Пример расчета — `grass_a.txt`

```
index=n1            → GrassA
fertility=n1        → вес 1/… при выборе без соседей
spreading=n2        → кластерный вес = 2 × число соседей
growRate=n1         → смена состояния каждый тик куба (быстро)
maxAmount=n190      → не более 190 на куб
health=N5,5,5,5     → 5 HP на всех стадиях
blockingHeight=40,0,0,0 → разбирается как [0,0,0,0]: трава НИКОГДА не блокирует
fruitingState=n-1   → NotFruiting: сбор плодов невозможен
state_0=40,0,1      → [0,0,1]: 2/3 остаются в состоянии 0, 1/3 переходит в следующее
state_1=41,1,2      → [1,1,2]
state_2=42,2,3      → [2,2,3]
state_3=43          → [3]
action_3=N1,1,1,0   → в финальном состоянии: 3/4 остаются, 1/4 погибает
```

Таким образом, тайл травы в среднем меняет состояние раз в 3 тика, а в финальной стадии имеет 25% шанс погибнуть каждый тик и освободить место для новых семян — постоянно обновляющийся покровный вид без плодов.

### Пример расчета — `wall.txt` (12 состояний, с префиксом `N`)

`blockingHeight=N0,0,2,3,4,7,9,10,10,13,13,14`, `health=N20,60,80,…,255`, `state_7=N7,7,8,8,6` (может деградировать на предыдущую стадию), `playerSeeded=n1`, `onlyOnUnprotectedZone=n1`, `maxAmount=n15`: возводимое игроками укрепление, существующее только в незащищенных зонах с лимитом 15 на куб, которое развивается (и периодически уменьшается) через 12 стадий вплоть до высоты 14 и 255 HP.

## Где хранятся данные тайлов

Состояние каждого тайла во время работы сервера представлено 7-байтовой структурой `PlantInfo` в файле растительного слоя зоны (`type, state, time, spawn, health, material, groundType`) — см. [Файлы зон](/ru/formats/zone-files/). Байт `spawn` представляет собой вероятность спавна на тайле, заложенную в файл зоны: `0` обозначает бесплодный тайл (растения на нем удаляются при валидации и никогда не прорастают); любое другое значение означает, что попытка прорастания проходит случайную проверку с вероятностью ≈ `spawn/256`. Сервер никогда не перезаписывает этот байт. В реальных данных каждый тайл `plants.0106.bin` имеет значение `0x83` (≈ 51%).

## Клиентский пакет данных

Метод `PlantRuleExtensions.GetPlantInfoForClient` отправляет клиенту для каждого вида: `index`, `mineral` (= fruitDefinition), `name`, `blocks` (blockingHeight), `health`.
